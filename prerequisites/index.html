OpenVMS Development Reimagined: From Alpha to x86 in 4 hours with XDE and AI

A half-day, hands-on workshop on OpenVMS x86-64. Everything runs in one local container: VMS/XDE (OpenVMS on Linux), VS Code in the browser, and Claude Code as an AI assistant. Every task can be done with or without AI.

Bringing your own laptop?

Prepare it before the workshop with the steps on this page: install and configure WSL2 (Windows only) and Docker. The workshop image itself is handed out on site, by download and on USB sticks.

Preparation

Install and configure the software below. Nothing else needs to be started: the workshop image and its start command are handed out on site.

Windows: WSL2 · PowerShell as Administrator

  1. Install WSL2 with Ubuntu. Reboot when asked, then create your Linux user.

    PowerShell
    wsl --install -d Ubuntu-24.04

  2. Update WSL and check its version: WSL version must be 2.0 or newer.

    PowerShell
    wsl --update
wsl --version

  3. Configure WSL: create %UserProfile%\.wslconfig with the content below. Leave the memory setting at the WSL default.

    PowerShell
    notepad $env:USERPROFILE\.wslconfig
    .wslconfig
    [wsl2]
networkingMode=mirrored

[experimental]
hostAddressLoopback=true

  4. Allow inbound connections to WSL in the Windows (Hyper-V) firewall.

    PowerShell
    Set-NetFirewallHyperVVMSetting -Name '{40E0AC32-46A5-438A-A0B2-2B479E8F2E90}' -DefaultInboundAction Allow

  5. Restart WSL so the settings take effect.

    PowerShell
    wsl --shutdown

Ubuntu · WSL2 terminal, or your Linux

  1. WSL with Ubuntu 20.04 or 22.04 only

    Enable systemd (Ubuntu 24.04 has it already). Then run wsl --shutdown in PowerShell and reopen Ubuntu.

    bash
    grep -q '^systemd=true' /etc/wsl.conf 2>/dev/null || printf '[boot]\nsystemd=true\n' | sudo tee -a /etc/wsl.conf

  2. Install Docker and zstd (for unpacking the workshop image), start Docker, and allow your user to use it. Then log out and in again (WSL: wsl --shutdown in PowerShell, reopen Ubuntu).

    bash
    sudo apt-get update
sudo apt-get install -y docker.io zstd
sudo systemctl enable --now docker
sudo usermod -aG docker $USER

  3. Check the installation.

    bash
    docker version              # shows both "Client" and "Server"
wslinfo --networking-mode   # WSL only: mirrored

  4. Check that the workshop ports are free: 8080, 6080, 5910, 6010, 3330 on 127.0.0.1 must not be used by other programs. Each check must print nothing.

    bash · Linux or Ubuntu in WSL2
    ss -ltn | grep -E ':(8080|6080|5910|6010|3330)\b'
    PowerShell · Windows (mirrored networking shares ports with WSL)
    Get-NetTCPConnection -State Listen -LocalPort 8080,6080,5910,6010,3330 -ErrorAction SilentlyContinue

    If a port is used, find the program and close it, or change its port:

    bash
    sudo ss -ltnp | grep -E ':(8080|6080|5910|6010|3330)\b'   # program name in users:(...)
    PowerShell
    Get-NetTCPConnection -State Listen -LocalPort 8080,6080,5910,6010,3330 -ErrorAction SilentlyContinue |
    ForEach-Object { Get-Process -Id $_.OwningProcess } | Select-Object Id, ProcessName, Path

    If a port can't be freed, tell the instructor at the start of the workshop.

Any Linux user works: inside the workshop container everything runs as its own user (xdews, the OpenVMS user XDEWS), and no host files are used.

You're ready. Bring the laptop and its charger to the workshop; the image and the start command are handed out there.
