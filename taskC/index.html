Task C

Using Linux and OpenVMS developer tools together

Build an existing OpenVMS project from Linux with a Makefile that runs every OpenVMS step through xdecli: only changed sources are rebuilt, and independent compiles run in parallel.

1 · Introduction and setup

Your team maintains BILLING, an OpenVMS program in C, with one module in MACRO-32 and one in COBOL. Its build procedure build.com compiles every source file, one after another, in one process. It is not incremental: it compiles everything every time, even when you changed only one file. In this task Claude Code writes a Makefile for it. GNU make runs on Linux in your container and starts each OpenVMS step with xdecli, so it can skip what is up to date and run independent compiles at the same time.

Result
A Makefile that builds the same PCSI kits as build.com. After a change to one source file only that file is compiled again, and make -j6 compiles independent files at the same time.
Tools
The VSI C, MACRO-32 and COBOL compilers, librarian, linker and PCSI on VMS/XDE, an interactive DCL session, xdecli (runs one DCL command on VMS/XDE from bash), GNU make, and Claude Code.
Project
DKC300:[billing], on Linux /opt/xde/vms_os/V9.2/DKC300/billing: the team's git repository.
Time
About 45 minutes.

C2 · Incremental builds

make compares file times: a result is built again only if a file it depends on is newer. You change nothing, then one file, and watch what make does. The commands run in the bash terminal of C1, in billing.

  1. Build again without changing anything. Every result is newer than its sources, so make has nothing to do and does not start OpenVMS at all.

    bash terminal
    make
    expected output
    make: Nothing to be done for 'all'.

  2. Change one source file. touch gives src/tax.c a new time stamp, as if you had edited and saved it.

    bash terminal
    touch src/tax.c

  3. Build again. make compiles only tax.c, then redoes the steps that depend on it: the library, the link and the two kits. The 15 other sources are not compiled.

    bash terminal
    make
    expected output (shortened; your Makefile's lines may look different)
    xdecli 'cc/nolist/define=__USE_STD_IOSTREAM/object=[.src]tax.obj [.src]tax.c'
xdecli 'library/create [.src]billing.olb [.src]*.obj'
xdecli 'link/map=billing.map/executable=billing.exe main.obj,[.src]billing.olb/library'
xdecli 'product package billing/source=billing.pcsi$desc/destination=[]/material=[]/format=sequential/options=noconfirm'
rm -f 'DEMO-X86VMS-BILLING-V0100-0-1.PCSI$COMPRESSED'
xdecli 'product copy billing/source=[]/destination=[]/format=compressed/options=noconfirm'
✓ Checkpoint — in the output of step 3, exactly one cc command, for tax.c; a second make says Nothing to be done again.

C3 · Parallel builds

The 18 source files don't depend on each other, so make can compile them at the same time. Each xdecli call is its own OpenVMS process, and -j6 lets make run up to six of them at once.

  1. Delete the build output, so the next build is a full one, like @build.com in C0.

    bash terminal
    make clean

  2. Build everything with six jobs. make prints each command when it starts it, so the first six compile commands appear together, before any output; the next ones start as soon as one finishes.

    bash terminal
    make -j6

  3. OPTIONALWatch the parallel jobs. In the VMS/XDE view click htop, then run make clean and make -j6 again in the bash terminal: htop lists several VMS/XDE processes, one per running compile.

✓ Checkpoint — make -j6 builds the PCSI kit DEMO-X86VMS-BILLING-V0100-0-1.PCSI and the compressed kit DEMO-X86VMS-BILLING-V0100-0-1.PCSI$COMPRESSED, and its output starts with several cc commands in a row: they run at the same time.

Final · Compare with the reference

The Makefile below is the instructors' reference. Compare it with the one Claude wrote for you: the rules can be named or ordered differently, but the ideas are the same.

file · billing/Makefile (reference)
# Makefile - build the BILLING demo for OpenVMS from Linux.
#
# Every VMS step (compile, library, link, PCSI) is run by xdecli.
#
#   make          build everything up to the PCSI kits
#   make -j6      the same, compiling 6 files in parallel
#   make run      run BILLING.EXE
#   make clean    delete all build output (runs clean.com)

XDECLI = xdecli
CCOPT  = /nolist/define=__USE_STD_IOSTREAM

SRCS = $(wildcard src/*.c)
MARS = $(wildcard src/*.mar)
COBS = $(wildcard src/*.cob)
OBJS = $(SRCS:.c=.obj) $(MARS:.mar=.obj) $(COBS:.cob=.obj)
KIT  = DEMO-X86VMS-BILLING-V0100-0-1.PCSI
KITC = $(KIT)$$COMPRESSED

.PHONY: all run clean

all: $(KITC)

# 1. Compile each library source: src/<name>.c -> src/<name>.obj
src/%.obj: src/%.c src/billing.h
	$(XDECLI) 'cc$(CCOPT)/object=[.src]$*.obj [.src]$*.c'

# 1a. Assemble each MACRO-32 source: src/<name>.mar -> src/<name>.obj
src/%.obj: src/%.mar
	$(XDECLI) 'macro/object=[.src]$*.obj [.src]$*.mar'

# 1b. Compile each COBOL source: src/<name>.cob -> src/<name>.obj
src/%.obj: src/%.cob
	$(XDECLI) 'cobol/object=[.src]$*.obj [.src]$*.cob'

# 2. Create the object library
src/billing.olb: $(OBJS)
	$(XDECLI) 'library/create [.src]billing.olb [.src]*.obj'

# 3. Compile the main program
main.obj: main.c src/billing.h
	$(XDECLI) 'cc$(CCOPT)/include=[.src]/object=main.obj main.c'

# 4. Link the executable
billing.exe: main.obj src/billing.olb
	$(XDECLI) 'link/map=billing.map/executable=billing.exe main.obj,[.src]billing.olb/library'

# 5. Create the PCSI kit
$(KIT): billing.exe billing.pcsi$$desc billing.pcsi$$text
	$(XDECLI) 'product package billing/source=billing.pcsi$$desc/destination=[]/material=[]/format=sequential/options=noconfirm'

# 6. Create the compressed PCSI kit (delete the old one first, otherwise
#    PRODUCT COPY takes it as the source instead of the new kit)
$(KITC): $(KIT)
	rm -f '$(KITC)'
	$(XDECLI) 'product copy billing/source=[]/destination=[]/format=compressed/options=noconfirm'

run: billing.exe
	$(XDECLI) 'run billing.exe'

clean:
	$(XDECLI) '@clean.com'
In the MakefileWhy
src/%.obj: src/%.c …One rule, one xdecli call per object file. make can rebuild a single file and run several of these rules at once; build.com compiles everything in one process.
Three src/%.obj rules: .c, .mar, .cobOne per language: CC, MACRO or COBOL. For each object file make uses the rule whose source file exists.
/object=[.src]$*.objThe object file gets the lower-case name that make looks for on Linux. Without it, the compiler names it .OBJ.
[.src] in the commands, src/ in the rulesThe rules are for make on Linux; the commands are DCL and use OpenVMS directory syntax.
$$make reads $ itself, so a DCL $ (as in billing.pcsi$desc) is written $$.
rm -f before product copyTaken over from build.com: PRODUCT COPY would use an old compressed kit as its source.

Wrap-up

You built an existing OpenVMS project from Linux without changing it: GNU make decides what is out of date, and xdecli runs each step on OpenVMS. Independent files are compiled at the same time, and a change to one file costs one compile. The same works at your own site with VMS/XDE: the Makefile uses only GNU make, xdecli and the project's own DCL commands.

✓ Checkpoint — you can explain why make -j6 after a touch of one file compiles exactly one file, and why make -j6 can compile several files at once while build.com cannot.
